# 实验路线与保留理由

完整目录索引见 `evidence/handoff_inventory.json`。以下按研究问题组织；“保留”指配置、结果、源码及必要权重，不代表保留所有训练轮次。

| 实验 | 具体问题／变化 | 目前定位 |
|---|---|---|
| v13及早期MultiBlur | 修正官方预处理、模糊缓存和评估口径 | 历史基础；共享数据仍被后续使用，禁止整目录删除 |
| v33／v35／v36／v37 | dropout、增强与Alljoined单独训练 | 数据与增强对照；Alljoined旧评估不能直接比较原始200图 |

| v43／v53 | Local OT 辅助对齐 | 局部对齐基础，部分缓存被后续复用 |
| v55／v56／v57 | 同人试次混合、噪声、遮挡 | 重要增强消融；混合有收益，其他增量较小 |
| v58—v63 | 恢复监督与不同第一阶段checkpoint | 早期表示优于晚期表示的关键证据，避免只按blur聚合选恢复来源 |

| submission_*／ensemble相关 | 提交包与集成回放 | 原包及组件保留；不得混淆本地200图与隐藏成绩 |

## 文件层级

- `src/`、`run.py`、`configs/`：保留经过验证的可运行基线。
- `research/tools/`：当前研究源码，按原目录结构归档；后续开发从此查找。
- `evidence/source_blobs/`：内容寻址的不可变运行快照。用 `source_snapshots.json` 找回某run的原始文件名。
- `evidence/runs/`：小型原始配置、逐轮记录、结果及报告。大数组、权重、完整日志保留本地。
- `evidence/cleanup_plan.json`：删除的准确范围、保留策略和文件属性。

实验ID不能单独定义方法。判断是否重复实验时，应同时核对来源checkpoint、数据、训练目标、监督层、Raw/EMA、支持集与评估口径。
